# SRIC Core 0.5.12

SRIC Core 0.5.12 hardens shared operational failure boundaries used by all Sentinel Forge products.

## Changes

- Unexpected branded-CLI exceptions are contained and redacted by default; `SENTINEL_DEBUG=1` preserves explicit local developer traceback behavior.
- Web Command Console runner failures are sanitized and no longer expose raw operational secrets.
- Command-catalog construction failures now fail closed as structured HTTP 503 responses with bounded redacted detail instead of opaque HTTP 500 responses.
- Timed-out Web Console child processes use bounded terminate/kill waits and a background reaper when the final synchronous wait cannot complete.
- Recently pruned terminal Web Console jobs are retained in a bounded five-minute tombstone window so concurrent SSE/status readers cannot race job pruning into spurious not-found failures.
- Job failure text, operational event messages, metadata and provenance are redacted before persistence.
- Audit metadata/result redaction and common key/value secret patterns are expanded.
- Runtime compatibility documentation is aligned to the Web catalog contract used by downstream products.

## Safety invariants

The release does not weaken Scope Engine, Policy Engine, rate limiting, approval requirements, `shell=False`, fixed-runner execution, AI-disabled defaults, or evidence truth-state rules.

## Validation

Focused runtime behavior was reproduced locally for catalog-503 redaction, retained-job/SSE safety, final-wait background reaping, and job secret redaction. The focused harness completed `4 passed` after identifying and correcting a return-code race between the synchronous timeout path and the background reaper.

This focused result is not a substitute for the exact-commit release gate. GitHub-hosted CI for the branch is currently unable to allocate runners because the account is locked due to a billing issue; hosted jobs show `runner_id=0` and `steps=[]`. Full release evidence must not be claimed until the exact commit executes the repository and ecosystem gates.
