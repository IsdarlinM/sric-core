# SRIC Core 0.5.0 Release Candidate

## Public 0.5 surfaces

CLI:

```text
sric case inspect CASE.json [--required-evidence EVIDENCE_ID]
sric case fingerprint --type TYPE --subject SUBJECT --predicate PREDICATE --object OBJECT [--context JSON]
```

Local API:

```text
POST /api/v1/evidence-native/cases/analyze
POST /api/v1/evidence-native/claims/fingerprint
```

These operations organize/measure evidence only. They do not change claim truth state and cannot create a validated finding.

## Coordinated release validation

With all six repositories checked out as siblings at their candidate commits:

```text
python sric-core/scripts/release-ecosystem.py --root .
```

The full gate builds an internal 0.5 wheelhouse, checks version compatibility, executes each repository release gate and then runs the cross-product contract smoke. The release remains a candidate until the generated ecosystem report is `PASS` for exact commit/tree identities.
